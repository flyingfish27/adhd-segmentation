## 测试方法(为什么不是端到端跑一遍)

端到端跑一次要十几分钟以上(光主 CV 阶段就有 828 次留一 CV、其中 RF 占 276 次 × 2.7 秒)。
故改为**隔离测试**:用 `ast` 从**真实的 `analysis/45_multivariate_cv.py`** 里抽出
`_load_progress` / `_save_progress` / `_seeds` / `_perm` 四个函数与 `PERM_BATCH` 常量,
在测试命名空间里 `exec` 执行,配一个廉价的 `one()`(命中与否由种子决定,可复现)。
**测的是本文件的真代码,不是副本** —— 若源文件改了,重跑本测试会自动测到新版本。

## 机制说明

| 项 | 值 |
|---|---|
| 存档粒度 | 每 `PERM_BATCH=500` 次置换存一次进度,外加每个组合跑完存一次整表 |
| 最坏丢失 | 一批 500 次置换。RF 组合约 500×2.7s ≈ **22 分钟**;非 RF 组合约 **30 秒** |
| 进度文件 | `analysis/.B_perm_progress.json`(tag → [已完成次数, 命中数]) |
| 整表快照 | `analysis/.B_multivariate.partial.csv` |
| 两者归属 | **不入版本控制**(已加进 `.gitignore`);正常跑完脚本会自己删掉 |
| 未保护的部分 | **主指标 CV 阶段**(置换之前,约 13 分钟量级)。它短、且确定性,重跑必得同表 |

## 一处必须知情的行为改变

原实现的随机种子取自全局 `rng` 的**顺序消耗**(`rng.integers(0,1e9,NPERM)`),
种子取决于「这是第几次调用 `perm_reg`/`perm_clf`」。**一旦中断续跑,`rng` 的位置对不上,
此后所有组合的种子全部改变** —— 结果虽仍是合法的置换检验,但**不可复现**。

新实现按 `(track, target, model, k)` 用 SHA-256 确定性派生种子,与调用顺序无关(测试 1)。

**代价(须知情)**:本改动使结果与「改动前一口气跑完」**不逐格相同**,因为种子生成方式变了。
两者都是合法的置换检验;新方式的可复现性更强(断在哪儿、续几次,每个组合拿到的种子完全相同)。
